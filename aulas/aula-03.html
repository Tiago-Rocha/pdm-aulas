void main() {
  final List<String> cidades = ['Ponta Delgada', 'Angra do Heroísmo', 'Horta'];
  final Map<String, double> temperaturas = {
    'Ponta Delgada': 21.0,
    'Angra do Heroísmo': 20.5,
    'Horta': 19.0,
  };
  final Set<String> ilhas = {'São Miguel', 'Terceira', 'Faial', 'Terceira'};

  cidades.add('Vila do Porto');
  print(cidades.length);                     // 4
  print(ilhas.length);                       // 3: um Set não guarda repetidos
  print(ilhas.contains('Pico'));             // false

    print('$c → ${temperaturas[c] ?? 'sem dados'}');
  }
}

4. Coleções: map, where e reduce em três linhas só para ler

As três recebem uma função e aplicam-na a cada elemento. Chamam-se funções de ordem superior, e resolvem quase tudo o que se faz com coleções.

ChamadaResultadoO que faz
[🌽, 🐮, 🐔].map(cozinhar)[🍿, 🍔, 🍳]Transforma cada elemento. Sai com o mesmo tamanho.
[🍿, 🍔, 🍳].where(vegetariano)[🍿, 🍳]Fica só com os que passam no teste. Pode encolher.
[🍿, 🍔, 🍳].reduce(comer)💩Junta tudo num só valor.

Em Dart, o filter de outras linguagens chama-se where. As três existem em qualquer Iterable: listas, sets, e entries, keys ou values de um Map.

Adaptado do exemplo em JavaScript de Steven Luscher.

Nada para escrever aqui. A função passada é o "cozinhar", o "vegetariano" e o "comer"; no slide seguinte são as lambdas (e) => .... Insistir: map não muda o tamanho, where pode, reduce devolve um só valor.

4. Coleções (2 de 3): where, map e reduce

// Cidades com 20 °C ou mais
final quentes = <String>[];
for (final e in temperaturas.entries) {
  if (e.value >= 20) quentes.add(e.key);
}

// Soma das temperaturas
var soma = 0.0;
for (final t in temperaturas.values) {
  soma += t;
}
  // ...continua dentro do main
  final quentes = temperaturas.entries
      .where((e) => e.value >= 20)           // fica com as entradas que passam no teste
      .map((e) => e.key)                     // de cada entrada, só a chave
      .toList();
  print(quentes);                            // [Ponta Delgada, Angra do Heroísmo]

  final soma = temperaturas.values.reduce((a, b) => a + b);
  print((soma / temperaturas.length).toStringAsFixed(1));   // 20.2
}
Ler o bloco de cima em voz alta e depois mostrar que o de baixo faz exatamente o mesmo. No reduce, a é o acumulado e b o próximo elemento. É o que o exercício 4 pede sobre entries.

4. Coleções (3 de 3): spread, if e for dentro do literal

final tudo = <String>[];
tudo.addAll(cidades);
if (ilhas.length > 3) tudo.add('Lajes');
for (final i in ilhas) tudo.add('Ilha $i');
  // ...continua dentro do main
  final tudo = [
    ...cidades,                              // spread: todos os elementos de cidades
    if (ilhas.length > 3) 'Lajes',           // só entra se a condição for verdadeira
    for (final i in ilhas) 'Ilha $i',        // um elemento por ilha
  ];
  print(tudo.length);                        // 7
}
Ligar ao lib/main.dart do início da aula: o children de um Column é uma lista normal, por isso aceita if e for lá dentro. É assim que se mostra um widget só quando há dados.

4. Coleções: o que interessa

  • List, Map e Set são genéricos: List<String>, Map<String, double>. Com final cidades = [...] o tipo é inferido e é o mesmo. Escreve-se quando a coleção começa vazia: <String>[], <String, double>{}, <String>{}. Um {} vazio sem tipo é um Map.
  • where, map, reduce, fold, any, every, firstWhere vivem em qualquer Iterable. Devolvem iteráveis preguiçosos; toList() materializa. Tudo o que fazem também se escreve com um ciclo: são atalhos, não magia.
  • Spread ..., if e for dentro de literais de coleção. Em Flutter, isto serve para construir listas de widgets condicionalmente.
Column(
  children: [
    const Text('Previsão'),
    if (chove) const Icon(Icons.umbrella),
    for (final c in cidades) Text(c),
  ],
)

enum TipoTempo { sol, nublado, chuva, trovoada }

class Previsao {
  final String cidade;
  final DateTime dia;
  final double tMin;
  final double tMax;
  final TipoTempo tipo;

  const Previsao({
    required this.cidade,
    required this.dia,
    required this.tMin,
    required this.tMax,
    this.tipo = TipoTempo.sol,
  });

  double get amplitude => tMax - tMin;
  bool get chove => tipo == TipoTempo.chuva || tipo == TipoTempo.trovoada;

}

5. Classes: o que interessa

  • Campos final + construtor const com this.campo: a forma idiomática de modelo de dados imutável. É o que será usado para os dados da API.
  • get define propriedades calculadas. copyWith é o padrão para "uma cópia com uma alteração", central em gestão de estado.
  • enum com .name. Amanhã: enums com valores e métodos.

6. Controlo de fluxo e switch com padrões

String icone(TipoTempo t) => switch (t) {
      TipoTempo.sol => '☀️',
      TipoTempo.nublado => '☁️',
      TipoTempo.chuva => '🌧️',
      TipoTempo.trovoada => '⛈️',
    };

String aviso(double vento) {
  if (vento >= 90) return 'vermelho';
  if (vento >= 70) return 'laranja';
  if (vento >= 50) return 'amarelo';
  return 'verde';
}

void main() {
  for (final t in TipoTempo.values) {
    print('${t.name}: ${icone(t)}');
  }
  var i = 0;
  while (i < 3) { print(aviso(40.0 + i * 25)); i++; }
}

O switch como expressão é exaustivo: se um valor novo entrar no enum sem ser tratado, o compilador avisa. Em mobile isto evita ecrãs em branco quando a API devolve um estado novo.

Git e GitHub: primeiro repositório

Objetivo: os exercícios de hoje guardados num repositório próprio no GitHub, com commit e push feitos a partir do VS Code. Passos completos na secção Git do guia.

  1. No GitHub: New repository → nome pdm-dart → marcar Add a README file → Create.
  2. No VS Code: Ctrl+Shift+P → Git: Clone → colar o URL do repositório → escolher a pasta de trabalho (C:\dev) → abrir o projeto. Se aparecer Restricted Mode, carregar em Trust.
  3. Criar exercicio1.dart a exercicio6.dart com o código do DartPad (o 5 e o 6 podem ficar no mesmo ficheiro). Confirmar que correm: dart run exercicio1.dart.
  4. Vista Source Control (Ctrl+Shift+G): mensagem Exercícios de Dart das aulas 2 e 3 → Commit → Sync Changes.
  5. Na primeira vez, o browser abre para autorizar o acesso ao GitHub. Depois de autorizado, não volta a pedir password neste computador.
  6. Abrir o repositório no GitHub e confirmar que os ficheiros lá estão.
Reserva os últimos 20 minutos. Erro típico: commit sem user.name e user.email configurados (o VS Code pede). Segundo erro típico: clonar para o OneDrive. Quem não tiver o Git instalado faz par com um colega e repete em casa.

Git: o que interessa

  • Commit é uma fotografia de todo o projeto com legenda e data. Não se apaga nenhuma; pode-se voltar a qualquer uma.
  • Push envia as fotografias para o GitHub; pull traz as que outros fizeram. O repositório local e o remoto são cópias completas.
  • Mensagens de commit dizem o que mudou e porquê: "Adiciona exercício 3 (funções)" e não "coisas".
  • A partir de sexta-feira, cada aula começa com um git clone. Mais tarde, o projeto de grupo vive inteiro no GitHub, com branches e pull requests.
