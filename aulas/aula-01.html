Apresenta-te em dois minutos: o que fazes, onde, com que stack, há quantos anos. Pergunta quem já instalou o Flutter e quem trouxe telemóvel Android e cabo. Isso decide quanto tempo a prática vai precisar.

Cinco ferramentas: o que é cada uma

Dois minutos com o diagrama projetado; percorre os cartões por ordem: local de trabalho, caixa de ferramentas, fornecedor de peças, álbum, cópia partilhada, e onde a app corre. Pergunta habitual: "para que serve o Android Studio se escrevemos no VS Code?" Pelas peças (SDK) e pelo emulador; pode nunca ser aberto para editar. Cada ferramenta volta a aparecer quando for usada.

Antes de descarregar: a pasta de trabalho

  1. Windows: abrir o Explorador de Ficheiros → Este PC → Disco Local (C:) → botão direito → Novo → Pasta → nome dev. Resultado: C:\dev.
  2. macOS e Linux: no Terminal, mkdir ~/dev.
  3. Esta pasta é para o Flutter SDK e para os projetos. Nunca no OneDrive, nem em Documentos ou Ambiente de Trabalho, nem em caminhos com espaços ou acentos.
Downloads e instalação são momentos diferentes Os instaladores que se seguem ficam na pasta Transferências do browser, e isso não interessa. Cada programa instala-se na sua pasta por defeito quando o instalador corre. A única escolha de pasta em toda a instalação é o download do Flutter SDK, mais tarde, e a resposta é C:\dev.
Confirma na sala que ninguém cria a pasta dentro do OneDrive. Em muitos portáteis novos, Documentos e Ambiente de Trabalho são o OneDrive; por isso o C:\dev direto na raiz do disco.

Download 1 de 3: Android Studio

É o maior (1,2 GB) e por isso vai primeiro. Endereço: developer.android.com/studio.

  1. Carregar no botão, aceitar os termos, e deixar o ficheiro android-studio-…-windows.exe descarregar.
  2. Não instalar ainda: passar ao download seguinte enquanto este corre.
Projeta o slide e espera até veres a barra de download a andar em todos os portáteis. Quem não tiver espaço em disco (menos de 15 GB) descobre-o aqui; é melhor agora do que na sexta.

Download 2 de 3: Git (só quem não tem)

Endereço: git-scm.com/downloads/win. É pequeno (70 MB).

  1. macOS: o Git vem com xcode-select --install no Terminal. Linux: sudo apt-get install git.
  2. Não instalar ainda; passar ao download seguinte.
Dúvida frequente: "x64 ou ARM64?" Quase todos os portáteis Windows são x64; só os novos com Snapdragon são ARM64. Na dúvida, x64.

Download 3 de 3: Visual Studio Code (só quem não tem)

Endereço: code.visualstudio.com (100 MB).

  1. O ficheiro chama-se VSCodeUserSetup-x64-….exe. É o User Installer, que é o certo.
  2. Quem já tinha o VS Code está, em vez disto, a descarregar o Flutter SDK. Com os downloads a correr, criar a conta GitHub no slide seguinte.

Enquanto os downloads correm: conta GitHub

Endereço: github.com/signup. Quem já tem conta passa à frente.

  1. Email: o da escola ou o pessoal. Vai receber um código de confirmação.
  2. Password: pelo menos 15 caracteres, ou 8 com números e minúsculas. Guardar num gestor de passwords.
  3. Username: é o nome público. Vai aparecer em todos os repositórios e no currículo: convém ser apresentável (por exemplo, nome e apelido, sem números aleatórios).
  4. Resolver o desafio de verificação, inserir o código recebido por email, e escolher o plano Free.
O que a conta serve Enviar código para o GitHub (push), clonar os repositórios das aulas e, a partir do projeto, o repositório do grupo. Amanhã faz-se o primeiro push.
Não há captura desta página: o GitHub bloqueia browsers automáticos. Mostra-a ao vivo no projetor. Pede a todos que confirmem o email já: sem confirmação, o push falha amanhã.

O que muda quando um programa corre num telemóvel

Pede exemplos da turma: quando é que uma app vos falhou por falta de rede? O objetivo é sentirem que estes limites são reais. Cada cartão volta a aparecer como aula própria mais à frente (ciclo de vida na 3, permissões na 21, lojas na 29, memória e CPU na 17). Se perguntarem "só estes?": não, são os mais frequentes; interrupções, tamanhos de ecrã e acessibilidade vêm nas aulas 3, 5 e 8.

Como o Flutter desenha o ecrã

Analogia Um cinema. O sistema operativo empresta a sala e a tela; o Flutter é o projetor, que pinta cada imagem; o código da app é o guião que diz o que aparece em cada cena.
Não uses ainda as palavras framework, engine e embedder: isso é amanhã. Aqui chega "descrever, pintar, mostrar". Se perguntarem por desempenho: o motor é código nativo em C++ e pinta direto na placa gráfica.

Como vão ser as aulas

  • Crazy 8s: oito ideias de ecrã em oito minutos, uma por minuto, em papel. Usa-se em equipas de produto para não ficar preso na primeira ideia.
  • Material em todas as aulas: portátil com o ambiente instalado, telemóvel Android com cabo de dados, conta GitHub.
Diz que o projeto é decidido com a turma: a API do IPMA é a proposta, mas outra API aberta pode entrar. Não dês datas de sprints nem de enunciado. Sobre os testes: um ou dois, escolha múltipla, decidido na próxima semana.

Inteligência artificial e responsabilidade

  • Copilot, ChatGPT, Claude ou outra ferramenta podem ser usados. O docente usa-os diariamente.
  • Cada aluno é responsável pelo código que produz: com IA, à mão ou copiado. Cada pedaço tem de poder ser explicado por quem o entrega.
  • O objetivo é aprender a programar e perceber como as coisas funcionam, não passar à disciplina.
Diz isto com clareza e sem ameaça: não és contra a IA, usas IA. O que não aceitas é código que ninguém no grupo consegue explicar. Na defesa, cada membro responde por partes do código à escolha do docente.

Instalar 1 de 4: Git

  1. Abrir o instalador (Git-….exe) a partir das Transferências. Aceitar a licença e carregar em Next em todos os ecrãs, com duas exceções.
  2. Ecrã Choosing the default editor used by Git: se o VS Code já estiver instalado, escolher Use Visual Studio Code as Git's default editor; se não, deixar como está (muda-se depois no guia).
  3. Ecrã Choose a credential helper: confirmar Git Credential Manager. É o que permite entrar no GitHub pelo browser em vez de escrever passwords.
  4. Tudo o resto: Next, Next, Install, Finish. A instalação vai para Program Files\Git.
  5. Confirmar num terminal novo: git --version.
macOS e Linux Não há instalador: xcode-select --install no macOS, sudo apt-get install git no Linux.
O instalador do Git tem uma dúzia de ecrãs e assusta; diz que só dois interessam. Não há captura destas janelas (são do Windows); se quiseres, tira-as num portátil da turma para a próxima vez.

Instalar 2 de 4: VS Code e a extensão Flutter

  1. Abrir VSCodeUserSetup-x64-….exe. Aceitar a licença. No ecrã Select Additional Tasks, marcar Add to PATH e Add "Open with Code" action. Install, Finish.
  2. Abrir o VS Code. Menu Extensions: Ctrl+Shift+X. Escrever Flutter na pesquisa e instalar a extensão Flutter, autor Dart Code, a primeira da lista. Traz a extensão Dart com ela.

Instalar 3 de 4: Flutter SDK, a partir do VS Code

  1. Paleta de comandos: Ctrl+Shift+P. Escrever flutter new e escolher Flutter: Create New Project.
  2. Quando perguntar pelo SDK: Download SDK. Na janela de pasta, escolher C:\dev. Carregar em Clone Flutter e esperar (cerca de 2 GB).
  3. Quando terminar: Add SDK to PATH. Se aparecer um aviso sobre Google Analytics, OK.
  4. Fechar o VS Code e todos os terminais e voltar a abrir. Num terminal novo: flutter --version.
Se o comando não aparecer na paleta, a pasta está em Restricted Mode ou a extensão não instalou. Se flutter --version disser "não é reconhecido", 90% das vezes é um terminal antigo; os outros 10% são o PATH à mão, no guia.

Windows: modo de programador

O Flutter precisa de criar symlinks quando compila plugins, e o Windows só o permite com o modo de programador ligado. Sem isto, mais tarde aparece o erro Building with plugins requires symlink support.

  1. Num terminal: start ms-settings:developers. Ou menu Iniciar → Definições de programador.
  2. Ligar o interruptor Modo de programador e confirmar o aviso.

Instalar 4 de 4: Android Studio e o SDK

  1. Abrir android-studio-…-windows.exe: Next em tudo, Install, Finish. No primeiro arranque escolher Standard, aceitar as licenças e deixar descarregar o SDK (3 a 4 GB). Se o utilizador do Windows tiver espaços ou acentos no nome, escolher Custom e pôr o SDK em C:\dev\Android\Sdk (guia).
  2. No ecrã inicial: menu de três pontos (More Actions) → SDK Manager → separador SDK Tools → marcar Android SDK Command-line Tools (latest) → Apply → OK.
  3. Num terminal: flutter doctor --android-licenses e y a tudo. Depois flutter doctor: ✓ em Flutter, Android toolchain e Android Studio.
O SDK ainda está a descarregar em muitos portáteis quando chegas aqui; fica para casa. O que tem de ficar feito hoje é o passo 3 do Flutter (flutter --version a responder).

Quem terminar: primeira app, no telemóvel ou no emulador

Não é preciso hoje. Até sexta-feira é necessário um dos dois; qualquer um serve.

Opção A: telemóvel Android

  1. Opções de programador (7 toques em Número de compilação) e Depuração USB.
  2. Cabo de dados; aceitar o pedido de confiança no ecrã do telemóvel.
  3. flutter devices mostra o modelo.

Opção B: emulador

  1. Android Studio → menu de três pontos → Virtual Device Manager → +.
  2. Medium Phone ou um Pixel → Next → Finish (descarrega cerca de 1 GB).
  3. Arrancar pelo triângulo; flutter devices mostra-o. Pede 16 GB de RAM.
cd C:\dev
flutter create ola_mobile
cd ola_mobile
flutter run

Com a app a correr, mudar um texto em lib/main.dart, gravar, e carregar em r no terminal: hot reload.

Poucos chegam aqui na aula 1 e não faz mal. Deixa claro que ninguém precisa de telemóvel hoje; quem não tem Android faz o emulador em casa com o guia. Na quarta-feira verificamos quem tem um dos dois.

  • Command-line tools instaladas e flutter doctor --android-licenses aceite.

  • Até sexta: telemóvel Android com depuração USB, ou um emulador criado. Não é preciso amanhã.
  • Conta GitHub criada e email confirmado.
