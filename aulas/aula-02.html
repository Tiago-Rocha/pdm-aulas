Três camadas

CamadaEscrita emO que faz
FrameworkDartO que se usa no dia a dia: widgets (Material, Cupertino), layout, animações, gestos, tema. Código Dart aberto, dentro do SDK.
EngineC++Desenha (Impeller), executa o Dart (Dart VM em desenvolvimento, código AOT em release), trata de texto, imagens, e fala com a plataforma.
EmbedderKotlin/Java, Swift/Objective-C, C++Específico de cada sistema: cria a janela ou a Activity, entrega eventos de toque, ciclo de vida, acessibilidade, e canais para código nativo.

O sistema dá uma superfície e os toques. O resto é o Flutter.

Desenha no quadro se ajudar: caixa "SO" → superfície + toques → caixa "Flutter" → app; setas de volta para o hardware com a palavra "ponte". Hoje basta saber que a ponte existe.

Tudo é um widget

Um widget é um objeto Dart imutável que descreve um pedaço de interface. Compõem-se uns dentro dos outros numa árvore.

import 'package:flutter/material.dart';

void main() => runApp(const TempoApp());

class TempoApp extends StatelessWidget {
  const TempoApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: const Text('Tempo Açores')),
        body: const Center(child: Text('Ponta Delgada · 21 °C')),
      ),
    );
  }
}
Analogia O widget é a planta de um edifício: imutável e barata de redesenhar. O element é a obra em curso, que segue a planta e sabe onde está na árvore. O render object é o edifício construído, com dimensões e posição. Mudar a planta não deita o edifício abaixo: a obra compara a planta nova com a antiga e só mexe no que mudou.

build não desenha nada

Devolve a descrição do que deve existir. O framework compara a descrição nova com a anterior e só mexe no que mudou. Chamar build muitas vezes é normal e barato; é assim que o Flutter foi desenhado.

Três árvores, uma ideia
  • Widgets são a descrição: baratos, imutáveis, recriados a cada build.
  • Elements são a instância viva que liga uma descrição a uma posição na árvore.
  • RenderObjects fazem layout e pintura.
O programador escreve widgets; o framework gere as outras duas.

Para os testes: um widget é imutável; o que muda é o estado, e o estado vive noutro sítio.

Analogia build é uma lista de compras, não a ida às compras. Escrever a lista muitas vezes é barato; o framework é quem vai à loja, e só compra o que mudou em relação à lista anterior.

Hot reload, hot restart, rebuild

  • Hot reload (r): injeta o código alterado na Dart VM que está a correr no telemóvel e volta a chamar build. O estado mantém-se: um formulário meio preenchido no terceiro ecrã continua lá. Menos de um segundo.
  • Hot restart (R): reinicia a app do zero, mantendo a compilação. Necessário quando muda o main, uma variável global, ou o tipo de um estado.
  • Rebuild completo: quando mudam dependências no pubspec.yaml, código nativo, ou recursos. Voltar a correr flutter run.
Analogia Hot reload é trocar a receita a meio de cozinhar sem deitar fora o que já está na panela: o código muda, o estado fica. Hot restart deita fora a panela e começa de novo, mas com a cozinha já montada (a compilação). O rebuild completo é montar a cozinha outra vez.

Porquê Dart

  • Null safety: o compilador sabe se uma variável pode ser null. Uma família inteira de crashes desaparece antes de a app correr.
  • Sintaxe familiar: quem sabe JavaScript, Java, Kotlin ou PHP moderno lê Dart no primeiro dia.
  • Feito para interfaces: garbage collector afinado para muitos objetos pequenos (os widgets), async/await na linguagem, isolates para trabalho pesado sem bloquear o ecrã.

Escrever o código em vez de o copiar Escrever pratica a sintaxe; copiar não. Os erros do compilador fazem parte do exercício: convém lê-los. Os blocos marcados «só para ler» não se escrevem: servem para comparar.

1. Variáveis e tipos

void main() {
  var cidade = 'Ponta Delgada';   // tipo inferido: String
  int dia = 21;
  double temperatura = 21.5;
  bool chove = false;
  final ilha = 'São Miguel';      // atribuído uma vez, em runtime
  const maxDias = 5;              // constante em tempo de compilação

  print('$cidade, $ilha: $temperatura °C, chuva: $chove');
  print('Dia ${dia + 1} de $maxDias');
}

1. Variáveis e tipos: o que interessa

  • var infere o tipo e fixa-o. cidade = 3; é erro de compilação.
  • final para valores que não mudam depois de atribuídos. É a escolha por defeito; var só quando é preciso reatribuir.
  • const é para constantes conhecidas em compilação. Em Flutter, const aparece em muitos widgets, por uma razão de desempenho.
  • Interpolação: $nome ou ${expressão}.
Exercício 1 No mesmo main, acrescentar double tMin = 17.0; e double tMax = 23.0;, calcular a amplitude (tMax - tMin) e imprimir, com interpolação e uma casa decimal (toStringAsFixed(1)), exatamente: Amplitude: 6.0 °C.

2. Null safety

void main() {
  String nome = 'Horta';
  String? alcunha;            // pode ser null; tem de ser declarado com ?

  // nome = null;             // erro de compilação
  print(alcunha ?? 'sem alcunha');        // ?? dá um valor por defeito
  print(alcunha?.length);                 // ?. só chama se não for null → null
  alcunha = 'Cidade do Mar';
  print(alcunha.length);                  // o compilador já sabe que não é null aqui

  late String descricao;      // prometo inicializar antes de usar
  descricao = '$nome, $alcunha';
  print(descricao);
}

2. Null safety: o que interessa

  • Por defeito nada pode ser null. String? é um tipo diferente de String.
  • ??, ?. e ??= são os operadores do dia a dia.
  • ! força ("confio que não é null") e é uma origem frequente de crashes. Convém evitá-lo.
  • Isto interessa em mobile porque quase tudo o que vem da rede ou do disco pode faltar.
Exercício 2 No mesmo main, acrescentar int? humidade; e uma linha que imprime Humidade: n/d quando é null e Humidade: 80% quando tem valor, sem usar ! (dica: humidade == null ? 'n/d' : '$humidade%', ou ??). Testar as duas situações: uma vez antes e outra depois de humidade = 80;.

3. Funções

double celsiusParaFahrenheit(double c) => c * 9 / 5 + 32;

String descreve(String cidade, {required double tMax, double? tMin, bool chuva = false}) {
  final min = tMin == null ? '' : ', mín $tMin';
  return '$cidade: máx $tMax$min${chuva ? ', chuva' : ''}';
}

void main() {
  print(celsiusParaFahrenheit(21));
  print(descreve('Angra', tMax: 24));
  print(descreve('Horta', tMax: 22, tMin: 17, chuva: true));

  final formatar = (double t) => '${t.round()} °C';   // função como valor
  print(formatar(21.6));
}

3. Funções: o que interessa

  • Parâmetros nomeados entre chavetas: {required double tMax, bool chuva = false}. Em Flutter quase tudo usa parâmetros nomeados.
  • required obriga; um valor por defeito torna opcional; ? permite null.
  • Sintaxe => para funções de uma expressão. Funções são valores: podem guardar-se e passar-se.
Exercício 3 Escrever String classifica({required double t}) que devolve 'frio' abaixo de 15, 'ameno' até 25 e 'quente' acima. Depois usá-la dentro de descreve, para descreve('Horta', tMax: 22, tMin: 17, chuva: true) passar a devolver Horta: máx 22.0, mín 17.0, chuva (ameno).
