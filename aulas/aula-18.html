O objetivo de hoje: um PR do princípio ao fim

  1. Branch: a partir do main atualizado, um branch com o nome da frente.
  2. Trabalho: commits pequenos, cada um com uma frase que diz o que mudou.
  3. PR: push do branch e, no GitHub, Compare & pull request. Escolham um colega em Reviewers.
  4. Review: o colega abre Files changed, comenta o que não percebe e, quando estiver bem, Approve.
  5. Merge: Merge pull request e Delete branch. Todos fazem pull do main.
Pronto Sai daqui um PR com review e merge no main, por grupo. Pequeno e acabado vale mais do que grande e aberto.
É isto que se avalia no processo: branches, PRs revistos por outra pessoa, commits com mensagens que dizem o que mudou. Se um grupo tiver a frente grande, partam em dois PRs: o primeiro pode ser só o tema ou só o router com ecrãs vazios.

Os comandos, pela ordem

git checkout main
git pull
git checkout -b conta

git add .
git commit -m "Conta: registo e login"
git push -u origin conta

git checkout main
git pull
  • O primeiro bloco antes de começar; o segundo cada vez que uma parte funciona; o terceiro depois do merge, em todos os computadores do grupo.
  • Funcionam iguais no PowerShell e no terminal do Mac. O nome do branch é o da vossa frente: conta, navegacao ou design-system.
Erro clássico: trabalhar no main sem reparar. Se acontecer antes do commit, git checkout -b conta leva as mudanças para o branch novo. Outro: o push pede login; no Windows abre o browser, no Mac pode pedir um token (o gh auth login resolve).
