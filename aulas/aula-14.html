Começar: o repositório de hoje

git clone https://github.com/Tiago-Rocha/pdm-aula-13.git
cd pdm-aula-13
flutter pub get
  1. Abre a pasta no VS Code. O clientId e o clientSecret estão na issue #1 do teu repositório pdm-miniprojeto.
  2. No terminal do VS Code, numa só linha, com os teus valores: flutter run -d chrome --dart-define=CLIENT_ID=pdm-ab12cd --dart-define=CLIENT_SECRET=o-teu-segredo
  3. Tens de ver a lista das ilhas, cada uma com a fotografia. Mão no ar quando aparecer.
  4. Abre um segundo terminal (o + do painel do terminal) para os comandos git. No primeiro, onde corre a app, r é hot reload, R é hot restart e q fecha.
Aparece 401: clientId ou clientSecret errados.? Faltam os dois --dart-define ou têm um erro. O F5 do VS Code não os passa: corre pelo terminal. As credenciais nunca vão para o código nem para o git.
Dez minutos, e só se avança com toda a gente com as ilhas no ecrã. O main já é o código arrumado por pastas. Problemas mais comuns: as barras invertidas para partir a linha (no PowerShell do Windows não funcionam: tudo numa linha); trocar o clientId com o clientSecret; espaços à volta do =; carregar em F5 (corre sem credenciais e dá o 401); sem a issue #1 no repositório, a pessoa não recebeu credenciais. Quem não conseguir de todo segue com o colega do lado até ao passo 1, que corre sem credenciais. O provider já está no pubspec.yaml.

Construir em conjunto: a tua peça

Hoje a turma constrói as ilhas favoritas: uma estrela em cada ilha, um contador e um ecrã só com as favoritas. Cada pessoa recebe uma peça, de uma das três camadas.

As peças são distribuídas pela API: quem entra recebe a que tem menos gente. Seis peças: o repository a fingir (dados), o FavoritesNotifier e o MultiProvider (estado), a estrela, o contador e o ecrã das favoritas (UI). Projeta o placar (slide seguinte). Quando alguém acaba, pergunta-lhe em voz alta: em que camada está a tua peça, e com quem fala? Depois manda-o ajudar alguém da lista "Ainda a construir".

Placar: a app a crescer

Cada barra é uma camada; enche com as peças de quem lá está. A meta é a app inteira em vinte minutos. A barra só chega ao fim quando todos da camada acabam: quem acaba ajuda. No fim, junta as peças em voz alta, de baixo para cima: o repository a fingir dá as ilhas, o notifier guarda as favoritas, o MultiProvider põe-no na árvore, a estrela e o contador leem-no e mudam-no, o ecrã das favoritas lê os dois notifiers.

O branch passo-2 tem as seis peças da turma, juntas. Corre sem credenciais: as ilhas vêm do repository a fingir.

  1. Marca o Pico e o Corvo: o contador mostra 2.
  2. Abre as Favoritas pela estrela de cima e tira o Corvo. Volta atrás: na lista, o Corvo já não tem estrela.
  3. Abre no VS Code o ficheiro da tua peça e encontra-a.
Pergunta à turma Para trocar a API pelo repository a fingir, quantas linhas mudaram em screens/?
Respostas às perguntas. Zero. Só o main escolhe o repository (--dart-define=FAKE=true). É a prova de que a arrumação de ontem funciona. Fechar a app perde as favoritas: estão só em memória. Guardar no telemóvel fica para mais à frente, e será um repository novo em data/.

Parte a rede tu mesmo

  1. Fecha a app (q) e corre-a com a API verdadeira, com as tuas credenciais (o comando do início da aula).
  2. No Chrome da app, F12, separador Network. Clica com o botão direito num pedido a api-pdm.sublimecipher.com e escolhe Block request domain.
  3. No terminal, R: a app arranca sem conseguir chegar à API.
  4. No separador Network request blocking, desliga o bloqueio e carrega em "Tentar de novo".
Pergunta à turma A mensagem de erro que apareceu serve a uma pessoa normal? O que devia dizer? E porque é que o ecrã aguentou a falha sem mudarmos nada?
Respostas às perguntas. A mensagem é técnica (algo como ClientException: XMLHttpRequest error): serve ao programador, não ao utilizador. Devia dizer algo como "Sem ligação à internet. Tenta de novo." O ecrã aguentou porque o repository lança a exceção, o notifier guarda-a em error e o ecrã só desenha o estado: a cozinha avisou o passe, o empregado deu a notícia. Mensagens para pessoas e repetir sozinho são o próximo passo da resiliência. Se o "Block request domain" não aparecer, usa More tools e depois Network request blocking e acrescenta api-pdm.sublimecipher.com.

Onde ficámos

  1. Cada peça da app tem uma camada: o repository em dados, os notifiers em estado, a estrela, o contador e os ecrãs em UI.
  2. O FakeForecastRepository troca a API sem mexer nos ecrãs.
  3. O FavoritesNotifier é partilhado por dois ecrãs, com MultiProvider.
  4. Quando a rede falha, o erro passa de camada em camada até ao ecrã, que só o desenha.
