3. Stack e Positioned: o cabeçalho da ilha revisão

/// Island photo with a gradient so that text on top of it stays readable.

Pergunta à turma Se tirar o fit: StackFit.expand, o que acontece à imagem? E se trocasse a ordem da imagem e do gradiente na lista? Em que sítio da lista tem de entrar o nome da ilha para ficar por cima dos dois?
  • Stack sobrepõe filhos pela ordem da lista: o último fica por cima. Positioned ancora a uma ou mais margens.
  • O gradiente por cima da imagem é uma técnica comum em apps de viagens para garantir contraste no texto.
Respostas às perguntas. Sem StackFit.expand os filhos sem Positioned deixam de ser obrigados a ocupar o Stack: a imagem fica com o tamanho que couber mantendo a proporção, encostada em cima à esquerda, e pode sobrar uma faixa vazia ao lado; o gradiente, que não tem filho, encolhe para zero e desaparece. Trocando a ordem, o gradiente fica por baixo da imagem e deixa de se ver: o último da lista é o que fica por cima. Por isso o nome da ilha entra no fim da lista, onde está o TODO 2, dentro de um Positioned: é o passo 2.

Pergunta à turma Se a lista tivesse mil dias, qual das duas congelava a app? Porque é que a DaysRow embrulha a lista num SizedBox com altura? Para que serve o separatorBuilder?
Respostas às perguntas. Congelava a primeira: ListView(children: [...]) obriga a criar todos os widgets antes de mostrar o primeiro; o .builder e o .separated só chamam o itemBuilder para os que estão no ecrã. O SizedBox dá altura à lista horizontal: dentro do ListView vertical a altura disponível é infinita e a lista não saberia que altura ter. O separatorBuilder constrói o que fica entre dois itens seguidos, aqui 8 de espaço; é chamado uma vez menos do que o itemBuilder.

4. GridView: a grelha das ilhas

return GridView.extent(
  maxCrossAxisExtent: 160, // as many columns as fit, each up to 160 dp
  padding: const EdgeInsets.all(16),
  mainAxisSpacing: 8,
  crossAxisSpacing: 8,
  shrinkWrap: true, // takes only the height it needs, inside the ListView
  physics: const NeverScrollableScrollPhysics(), // the ListView scrolls
  children: [
    for (final i in islands)
      Card(
        clipBehavior: Clip.antiAlias,
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          children: [
            Expanded(child: Image.asset(i.image, fit: BoxFit.cover)),
            Padding(
              padding: const EdgeInsets.all(8),
              child: Text(i.name, textAlign: TextAlign.center),
            ),
          ],
        ),
      ),
  ],
);
Pergunta à turma Quantas colunas tem a grelha num telemóvel com 360 dp de largura? E numa janela de browser com 1200? Porque é que esta grelha precisa de shrinkWrap e de não fazer scroll?
Respostas às perguntas. GridView.extent não fixa o número de colunas: põe as que forem precisas para nenhuma célula passar dos 160 dp. Com 360 dp de largura dá 2 colunas, num telemóvel de 411 dp dá 3, e numa janela de 1200 dá 7. Quem está no Chrome vê isto ao vivo ao alargar a janela. O shrinkWrap faz a grelha ocupar só a altura de que precisa e o NeverScrollableScrollPhysics desliga-lhe o scroll, porque quem faz scroll é o ListView de fora. Sem o shrinkWrap, uma lista dentro de outra dá o erro "Vertical viewport was given unbounded height".

4. Listas: o que interessa

  • ListView(children: [...]) constrói todos os filhos, mesmo os que não se veem. Para 10 itens serve; para 1000, congela a app.
  • ListView.builder e .separated chamam o itemBuilder só para os itens visíveis e reciclam-nos ao fazer scroll. É assim que o feed do Instagram aguenta milhares de posts.
  • ListTile é a linha de lista Material pronta: leading, title, subtitle, trailing, onTap. Usa-a antes de inventar a tua.
  • GridView.count fixa o número de colunas; GridView.extent fixa a largura máxima de cada célula e calcula as colunas, o que é melhor para tablets.
  • scrollDirection: Axis.horizontal transforma qualquer lista numa fila deslizante.

Para os testes: ListView.builder constrói os itens sob demanda; ListView com children constrói todos.
