API Tempo Açores

Uma API REST mantida pelo docente: as ilhas e os trilhos dos Açores, a previsão real do IPMA, e um feed de relatos da turma com texto e fotografia. É a base do mini-projeto 2.

Endereço basehttps://api-pdm.sublimecipher.com
Documentação interativahttps://api-pdm.sublimecipher.com/docs (Swagger: experimentas cada pedido no browser)
Especificação OpenAPIhttps://api-pdm.sublimecipher.com/openapi.json
FormatoJSON em UTF-8; datas em ISO 8601; números como números
AutenticaçãoJWT: Authorization: Bearer <token> em todos os pedidos menos o do token

Primeiros passos

  1. O teu clientId e o teu clientSecret estão numa issue no teu repositório pdm-miniprojeto. São só teus.
  2. Abre a documentação interativa. Em POST /v1/auth/token, carrega em Try it out, preenche o pedido e carrega em Execute.
  3. Copia o accessToken, carrega em Authorize no topo da página e cola-o. A partir daí todos os pedidos levam o token.
  4. Experimenta GET /v1/islands/sao-miguel/forecast: é a previsão de hoje, vinda do IPMA.

Autenticação

Trocas o clientId e o clientSecret por um token, e mandas o token em cada pedido. O token dura 1 hora; quando a API responder 401, pede outro.

POST /v1/auth/token
Content-Type: application/json

{
  "clientId": "pdm-ab12cd",
  "clientSecret": "o-teu-segredo"
}
{
  "accessToken": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...",
  "tokenType": "Bearer",
  "expiresIn": 3600
}
GET /v1/islands
Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...
Segurança O token é um JWT: três partes em base64 separadas por pontos, assinado pela API. Qualquer pessoa pode ler o que está lá dentro (cola-o em jwt.io), mas ninguém o consegue alterar sem a chave do servidor. Por isso não tem segredos dentro, só quem és e quando expira. O clientSecret, esse sim, não pode ir para o código que fazes commit: guarda-o fora do git, por exemplo com --dart-define.

  • weatherType.category é um dos valores do enum WeatherType das aulas: sunny, partlyCloudy, cloudy, rain ou storm. A description é o texto do IPMA.
  • rainChance vai de 0 a 100. O IPMA não dá a velocidade do vento em km/h, só a classe: 1 fraco, 2 moderado, 3 forte, 4 muito forte.
  • A API pergunta ao IPMA no máximo de 30 em 30 minutos. Se o IPMA falhar, devolve a última previsão que tiver; se não tiver nenhuma, responde 502.

  • Só vêm os avisos amarelos, laranja e vermelhos, dos mais graves para os menos graves. Uma lista vazia é o caso normal: quer dizer que não há avisos, e a app tem de o dizer.
  • O IPMA dá os avisos por grupo de ilhas: AOR Grupo Oriental, ACE Grupo Central e AOC Grupo Ocidental. islandIds diz a que ilhas se aplica cada aviso; ?islandId=pico devolve só os da área do Pico.
  • type é um de wind, rain, seaState, thunderstorm, fog, snow, hot ou cold. O text pode vir vazio.

Favoritos

Os favoritos ficam na conta, não no telemóvel: dois telemóveis com o mesmo clientId veem os mesmos. Marcar e tirar são idempotentes: repetir o pedido dá sempre 204, por isso a app pode tentar outra vez sem medo.

Mais dados do IPMA

  • /v1/islands/{id}/sea: altura e período da ondulação, altura total do mar e temperatura da água para hoje e os dois dias seguintes. O IPMA só tem três pontos nos Açores (Ponta Delgada, Horta e Santa Cruz das Flores); location diz qual serve a ilha.
  • /v1/islands/{id}/observations: as estações do IPMA na ilha, cada uma com a sua última leitura (temperatura, humidade, vento, pressão, chuva). As horas estão em UTC. Cada estação mede o que pode: o que falta vem a null.
  • /v1/earthquakes: sismos dos últimos 30 dias na região, do mais recente para o mais antigo, com a magnitude, a profundidade, a ilha mais próxima e, se foi sentido, a intensidade e onde.

Os campos todos, com exemplos, estão na documentação interativa.

Relatos

Um relato é um texto, e opcionalmente uma fotografia, sobre o tempo numa ilha. O feed é da turma toda: todos veem os relatos de todos, com o nome do autor, e cada um só altera e apaga os seus. O campo mine diz se o relato é teu.

  • POST responde 201 com o relato criado; PUT responde 200 com o relato alterado; DELETE responde 204, sem corpo.
  • O texto tem de 1 a 500 caracteres. A fotografia tem até 8 MB; a API reduz para 1280 px no lado maior e grava em JPEG.
  • Alterar ou apagar um relato que não é teu dá 403.

Erros

Quando algo corre mal, o código HTTP diz o tipo de erro e o corpo explica-o em português:

{
  "error": {
    "code": "not_found",
    "message": "Não há nenhuma ilha com o id \"atlantida\"."
  }
}
CódigoQuandoO que a app deve fazer
400Pedido inválido: campo em falta, texto vazio ou longo, fotografia que não é imagemMostrar a message ao utilizador
401Sem token, token inválido ou expiradoPedir um token novo e repetir o pedido
403O relato não é teuNão mostrar editar e apagar nos relatos dos outros (mine)
404A ilha, o trilho ou o relato não existeMostrar "não encontrado"
413Fotografia com mais de 8 MBReduzir a fotografia antes de enviar
502O IPMA não respondeuMostrar um erro com "Tentar outra vez"

Em Dart

Com o pacote http (flutter pub add http). Os exemplos foram testados contra a API.

import 'dart:convert';
import 'package:http/http.dart' as http;

const base = 'https://api-pdm.sublimecipher.com';

Future<String> getToken(String clientId, String clientSecret) async {
  final res = await http.post(
    Uri.parse('$base/v1/auth/token'),
    headers: {'Content-Type': 'application/json'},
    body: jsonEncode({'clientId': clientId, 'clientSecret': clientSecret}),
  );
  if (res.statusCode != 200) {
    throw Exception(jsonDecode(res.body)['error']['message']);
  }
  return jsonDecode(res.body)['accessToken'];
}
final res = await http.get(
  Uri.parse('$base/v1/islands/faial/forecast'),
  headers: {'Authorization': 'Bearer $token'},
);
final days = jsonDecode(res.body)['days'] as List<dynamic>;
final req = http.MultipartRequest('POST', Uri.parse('$base/v1/reports'))
  ..headers['Authorization'] = 'Bearer $token'
  ..fields['islandId'] = 'faial'
  ..fields['text'] = 'Céu limpo na Horta, mar calmo.'
  ..files.add(await http.MultipartFile.fromPath('photo', file.path));
final res = await http.Response.fromStream(await req.send());
// 201: jsonDecode(res.body) é o relato criado, com photoUrl
final res = await http.put(

No Chrome, MultipartFile.fromPath não funciona (não há sistema de ficheiros): usa MultipartFile.fromBytes('photo', bytes, filename: 'foto.jpg') com os bytes que o seletor de imagens devolve.

Regras de uso

  • As credenciais são pessoais. Os pedidos ficam registados com o teu nome, e os relatos que publicares aparecem com ele à turma toda.
  • Os relatos são públicos dentro da turma: escreve como escreverias num grupo da turma. O docente pode apagar qualquer relato.
  • Faz cache do lado da app: a previsão só muda de 30 em 30 minutos, não precisas de a pedir a cada ecrã.
  • Se perderes o clientSecret, pede ao docente um novo.
