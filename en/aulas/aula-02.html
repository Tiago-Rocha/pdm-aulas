Three layers

LayerWritten inWhat it does
FrameworkDartWhat you use day to day: widgets (Material, Cupertino), layout, animations, gestures, theme. Open Dart code, inside the SDK.
EngineC++Draws (Impeller), runs the Dart code (Dart VM in development, AOT code in release), handles text and images, and talks to the platform.
EmbedderKotlin/Java, Swift/Objective-C, C++Specific to each system: creates the window or the Activity, delivers touch events, lifecycle, accessibility, and channels to native code.

The system provides a surface and the touches. The rest is Flutter.

Draw it on the board if it helps: "OS" box → surface + touches → "Flutter" box → app; arrows back to the hardware with the word "bridge". Today it is enough to know that the bridge exists.

Everything is a widget

A widget is an immutable Dart object that describes a piece of interface. They are composed one inside another in a tree.

import 'package:flutter/material.dart';

void main() => runApp(const TempoApp());

class TempoApp extends StatelessWidget {
  const TempoApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: const Text('Tempo Açores')),
        body: const Center(child: Text('Ponta Delgada · 21 °C')),
      ),
    );
  }
}
Analogy The widget is the blueprint of a building: immutable and cheap to redraw. The element is the building site, which follows the blueprint and knows where it is in the tree. The render object is the finished building, with dimensions and a position. Changing the blueprint does not knock the building down: the site compares the new blueprint with the old one and only touches what changed.

build does not draw anything

It returns the description of what should exist. The framework compares the new description with the previous one and only touches what changed. Calling build many times is normal and cheap; that is how Flutter was designed.

Three trees, one idea
  • Widgets are the description: cheap, immutable, recreated on every build.
  • Elements are the live instance that ties a description to a position in the tree.
  • RenderObjects do layout and painting.
The programmer writes widgets; the framework manages the other two.

For the tests: a widget is immutable; what changes is the state, and the state lives somewhere else.

Analogy build is a shopping list, not the shopping trip. Writing the list many times is cheap; the framework is the one that goes to the shop, and it only buys what changed since the previous list.

Hot reload, hot restart, rebuild

  • Hot reload (r): injects the changed code into the Dart VM running on the phone and calls build again. The state is kept: a half-filled form on the third screen is still there. Under a second.
  • Hot restart (R): restarts the app from scratch, keeping the build. Needed when main, a global variable, or the type of a state changes.
  • Full rebuild: when dependencies in pubspec.yaml, native code, or assets change. Run flutter run again.
Analogy Hot reload is swapping the recipe halfway through cooking without throwing away what is already in the pan: the code changes, the state stays. Hot restart throws the pan away and starts over, but with the kitchen already set up (the build). The full rebuild is setting up the kitchen again.

Why Dart

  • Null safety: the compiler knows whether a variable can be null. A whole family of crashes disappears before the app runs.
  • Familiar syntax: anyone who knows JavaScript, Java, Kotlin or modern PHP can read Dart on day one.
  • Made for interfaces: a garbage collector tuned for many small objects (the widgets), async/await in the language, isolates for heavy work without blocking the screen.

1. Variables and types

void main() {
  var city = 'Ponta Delgada';     // inferred type: String
  int day = 21;
  double temperature = 21.5;
  bool isRaining = false;
  final island = 'São Miguel';    // assigned once, at runtime
  const maxDays = 5;              // compile-time constant

  print('$city, $island: $temperature °C, rain: $isRaining');
  print('Day ${day + 1} of $maxDays');
}

1. Variables and types: what matters

  • var infers the type and fixes it. city = 3; is a compile error.
  • final for values that do not change once assigned. It is the default choice; var only when you need to reassign.
  • const is for constants known at compile time. In Flutter, const appears on many widgets, for a performance reason.
  • Interpolation: $name or ${expression}.
Exercise 1 In the same main, add double tMin = 17.0; and double tMax = 23.0;, compute the range (tMax - tMin) and print, with interpolation and one decimal place (toStringAsFixed(1)), exactly: Range: 6.0 °C.

2. Null safety

void main() {
  String name = 'Horta';
  String? nickname;           // can be null; has to be declared with ?

  // name = null;             // compile error
  print(nickname ?? 'no nickname');       // ?? gives a default value
  print(nickname?.length);                // ?. only calls if it is not null → null
  nickname = 'City of the Sea';
  print(nickname.length);                 // the compiler already knows it is not null here

  late String description;    // I promise to initialise it before use
  description = '$name, $nickname';
  print(description);
}

2. Null safety: what matters

  • By default nothing can be null. String? is a different type from String.
  • ??, ?. and ??= are the everyday operators.
  • ! forces it ("trust me, it is not null") and is a frequent source of crashes. Best avoided.
  • This matters on mobile because almost everything that comes from the network or the disk can be missing.
Exercise 2 In the same main, add int? humidity; and a line that prints Humidity: n/a when it is null and Humidity: 80% when it has a value, without using ! (hint: humidity == null ? 'n/a' : '$humidity%', or ??). Test both situations: once before and once after humidity = 80;.

3. Functions

double celsiusToFahrenheit(double c) => c * 9 / 5 + 32;

String describe(String city, {required double tMax, double? tMin, bool rain = false}) {
  final min = tMin == null ? '' : ', min $tMin';
  return '$city: max $tMax$min${rain ? ', rain' : ''}';
}

void main() {
  print(celsiusToFahrenheit(21));
  print(describe('Angra', tMax: 24));
  print(describe('Horta', tMax: 22, tMin: 17, rain: true));

  final format = (double t) => '${t.round()} °C';   // function as a value
  print(format(21.6));
}

3. Functions: what matters

  • Named parameters go between braces: {required double tMax, bool rain = false}. In Flutter almost everything uses named parameters.
  • required makes it mandatory; a default value makes it optional; ? allows null.
  • => syntax for single-expression functions. Functions are values: they can be stored and passed around.
Exercise 3 Write String classify({required double t}) that returns 'cold' below 15, 'mild' up to 25 and 'hot' above. Then use it inside describe, so that describe('Horta', tMax: 22, tMin: 17, rain: true) now returns Horta: max 22.0, min 17.0, rain (mild).
