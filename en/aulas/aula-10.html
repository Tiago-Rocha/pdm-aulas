Routes are a tree

  • Read it top to bottom: GoRouter has a frame, the frame has one branch per tab, each branch has its routes.
  • /island/pico = route / + child island/:id. That is why Pico opens inside the Previsão tab, with the bar visible.
Draw this tree on the board before showing the slide, from the passo-3 router.dart open in VS Code. Point at each bracket and ask "which box is this?". The idea that has to stick is the hierarchy: the frame (shell) is not a screen, it is what surrounds all screens. In lesson 9 the hardest part was this: understanding why the route / moved into a branch.

Ask the class You open Pico, go to Avisos and come back to Previsão. Why is Pico still there, and not the grid?
Answers to the questions. Because each StatefulShellBranch has its own stack, and indexedStack keeps all stacks alive, one under the other, like an IndexedStack: only the current tab's is visible. Switching tabs does not pop. The Previsão stack is still the grid with Pico on top. To get back to the grid: the back arrow, or tap Previsão again (the initialLocation: i == shell.currentIndex).

The frame's code

StatefulShellRoute.indexedStack(
  builder: (context, state, shell) => Scaffold(
    body: shell, // the current tab, with its own stack
    bottomNavigationBar: NavigationBar(
      selectedIndex: shell.currentIndex,
      onDestinationSelected: (i) =>
          shell.goBranch(i, initialLocation: i == shell.currentIndex),
      destinations: const [
        NavigationDestination(
          icon: Icon(Icons.wb_sunny_outlined),
          label: 'Previsão',
        ),
        NavigationDestination(
          icon: Icon(Icons.warning_amber),
          label: 'Avisos',
        ),
        NavigationDestination(
          icon: Icon(Icons.settings_outlined),
          label: 'Definições',
        ),
      ],
    ),
  ),
  branches: [
    // one StatefulShellBranch per tab, in the same order
  ],
),
  • shell.currentIndex: which tab is active. The bar highlights it.
  • shell.goBranch(i): switches to tab i, without destroying the others.
  • Destination i in the bar opens branch i. The order must be the same in both lists.
Ask the class You add a NavigationDestination and forget the branch. What happens when you tap the new tab?
Answers to the questions. goBranch(3) asks for a branch that does not exist and the app throws an error. The other way round, a branch without a destination, the app runs, but nobody can reach that tab. And if you put the Trilhos destination third and its branch fourth, the Trilhos tab opens Definições: the order is the only link between the two lists. A typical mistake in the mini-project.

push or go?

Use it whenExample
context.pushYou open a detail on top of the screen you are onFrom the grid to an island; from the list to a trail
context.goYou go somewhere else in the app, which has its own stackFrom the island to a trail in the Trilhos tab; a link in a notification
In Chrome the difference shows in the URL and in the arrow. Show it live on lesson 9's passo-3: swap context.push in IslandCard for context.go. It still works, because /island/pico is a child of / and go builds the stack with the grid and Pico on top. The difference appears when the destination is in another tab: then go switches tabs and the tab you came from stays as it was. That is exactly TODO 4 of the mini-project.

Recipe: a new tab

  1. The screen. A widget with a Scaffold and an AppBar, like the other tabs.
  2. The destination in the bar. A NavigationDestination with an icon and a label, in the position where you want to see it.
  3. The branch. A StatefulShellBranch in the same position, with the GoRoute for the tab's path.
  4. The detail, if there is one. A child route inside that GoRoute, with the parameter: ':id', with no leading /.
  5. The detail screen receives the id, looks the object up in the data and handles not finding it.
StatefulShellBranch(
  routes: [
    GoRoute(
      path: '/alerts',
      builder: (context, state) => const AlertsScreen(),
    ),
  ],
),

This is what you do in the mini-project, with Trilhos. The Previsão tab, with / and island/:id, is the complete model: it is in the same file.
