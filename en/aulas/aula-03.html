4. Collections (1 of 3): List, Map and Set

void main() {
  final List<String> cities = ['Ponta Delgada', 'Angra do Heroísmo', 'Horta'];
  final Map<String, double> temperatures = {
    'Ponta Delgada': 21.0,
    'Angra do Heroísmo': 20.5,
    'Horta': 19.0,
  };
  final Set<String> islands = {'São Miguel', 'Terceira', 'Faial', 'Terceira'};

  cities.add('Vila do Porto');
  print(cities.length);                      // 4
  print(islands.length);                     // 3: a Set does not keep duplicates
  print(islands.contains('Pico'));           // false
  print(temperatures['Horta']);              // 19.0; a missing key gives null

  for (final c in cities) {
    print('$c → ${temperatures[c] ?? 'no data'}');
  }
}

4. Collections: map, where and reduce in three lines read only

All three take a function and apply it to each element. They are called higher-order functions, and they solve almost everything you do with collections.

CallResultWhat it does
[🌽, 🐮, 🐔].map(cook)[🍿, 🍔, 🍳]Transforms each element. Comes out the same size.
[🍿, 🍔, 🍳].where(isVegetarian)[🍿, 🍳]Keeps only the ones that pass the test. Can shrink.
[🍿, 🍔, 🍳].reduce(eat)💩Combines everything into a single value.

In Dart, the filter of other languages is called where. All three exist on any Iterable: lists, sets, and the entries, keys or values of a Map.

Adapted from Steven Luscher's JavaScript example.

Nothing to type here. The function passed in is the "cook", the "isVegetarian" and the "eat"; on the next slide they are the lambdas (e) => .... Insist: map does not change the size, where can, reduce returns a single value.

4. Collections (2 of 3): where, map and reduce

// Cities at 20 °C or more
final hot = <String>[];
for (final e in temperatures.entries) {
  if (e.value >= 20) hot.add(e.key);
}

// Sum of the temperatures
var sum = 0.0;
for (final t in temperatures.values) {
  sum += t;
}
  // ...continues inside main
  final hot = temperatures.entries
      .where((e) => e.value >= 20)           // keeps the entries that pass the test
      .map((e) => e.key)                     // from each entry, only the key
      .toList();
  print(hot);                                // [Ponta Delgada, Angra do Heroísmo]

  final sum = temperatures.values.reduce((a, b) => a + b);
  print((sum / temperatures.length).toStringAsFixed(1));   // 20.2
}
Read the top block aloud and then show that the bottom one does exactly the same. In reduce, a is the accumulated value and b the next element. It is what exercise 4 asks for over entries.

4. Collections (3 of 3): spread, if and for inside the literal

final all = <String>[];
all.addAll(cities);
if (islands.length > 3) all.add('Lajes');
for (final i in islands) all.add('Island $i');
  // ...continues inside main
  final all = [
    ...cities,                               // spread: every element of cities
    if (islands.length > 3) 'Lajes',         // only goes in if the condition is true
    for (final i in islands) 'Island $i',    // one element per island
  ];
  print(all.length);                         // 7
}
Link it to the lib/main.dart from the start of the lesson: the children of a Column is an ordinary list, so it accepts if and for inside it. That is how you show a widget only when there is data.

4. Collections: what matters

  • List, Map and Set are generic: List<String>, Map<String, double>. With final cities = [...] the type is inferred and it is the same. You write it out when the collection starts empty: <String>[], <String, double>{}, <String>{}. An empty {} with no type is a Map.
  • where, map, reduce, fold, any, every, firstWhere live on any Iterable. They return lazy iterables; toList() materialises them. Everything they do can also be written with a loop: they are shortcuts, not magic.
  • Spread ..., if and for inside collection literals. In Flutter, this is used to build lists of widgets conditionally.
Column(
  children: [
    const Text('Forecast'),
    if (isRaining) const Icon(Icons.umbrella),
    for (final c in cities) Text(c),
  ],
)

5. Classes (1 of 2)

enum WeatherType { sun, cloudy, rain, thunderstorm }

class Forecast {
  final String city;
  final DateTime day;
  final double tMin;
  final double tMax;
  final WeatherType type;

  const Forecast({
    required this.city,
    required this.day,
    required this.tMin,
    required this.tMax,
    this.type = WeatherType.sun,
  });

  double get range => tMax - tMin;
  bool get isRaining => type == WeatherType.rain || type == WeatherType.thunderstorm;
  // continues on the next slide
}

  // ...inside Forecast
  Forecast copyWith({double? tMin, double? tMax, WeatherType? type}) => Forecast(
        city: city,

        tMax: tMax ?? this.tMax,

void main() {
  final today = Forecast(city: 'Ponta Delgada', day: DateTime(2026, 9, 22), tMin: 17, tMax: 23);
  print(today);
  print(today.range);
  final tomorrow = today.copyWith(tMax: 25, type: WeatherType.rain);
  print('$tomorrow, raining: ${tomorrow.isRaining}');
}

5. Classes: what matters

  • final fields + a const constructor with this.field: the idiomatic form of an immutable data model. It is what will be used for the API data.
  • get defines computed properties. copyWith is the pattern for "a copy with one change", central to state management.
  • enum with .name. Tomorrow: enums with values and methods.

6. Control flow and switch with patterns

String icon(WeatherType t) => switch (t) {
      WeatherType.sun => '☀️',
      WeatherType.cloudy => '☁️',
      WeatherType.rain => '🌧️',
      WeatherType.thunderstorm => '⛈️',
    };

String warning(double wind) {
  if (wind >= 90) return 'red';
  if (wind >= 70) return 'orange';
  if (wind >= 50) return 'yellow';
  return 'green';
}

void main() {
  for (final t in WeatherType.values) {
    print('${t.name}: ${icon(t)}');
  }
  var i = 0;
  while (i < 3) { print(warning(40.0 + i * 25)); i++; }
}

The switch as an expression is exhaustive: if a new value enters the enum without being handled, the compiler warns you. On mobile this avoids blank screens when the API returns a new state.

Git and GitHub: first repository

Goal: today's exercises saved in a repository of your own on GitHub, with commit and push done from VS Code. Full steps in the Git section of the guide.

  1. On GitHub: New repository → name pdm-dart → tick Add a README file → Create.
  2. In VS Code: Ctrl+Shift+P → Git: Clone → paste the repository URL → choose the working folder (C:\dev) → open the project. If Restricted Mode appears, click Trust.
  3. Create exercise1.dart to exercise6.dart with the code from DartPad (5 and 6 can stay in the same file). Confirm that they run: dart run exercise1.dart.
  4. Source Control view (Ctrl+Shift+G): message Dart exercises from lessons 2 and 3 → Commit → Sync Changes.
  5. The first time, the browser opens to authorise access to GitHub. Once authorised, it does not ask for a password again on this computer.
  6. Open the repository on GitHub and confirm that the files are there.
Keep the last 20 minutes for this. Typical mistake: commit without user.name and user.email configured (VS Code asks). Second typical mistake: cloning into OneDrive. Anyone who does not have Git installed pairs up with a classmate and repeats it at home.

Git: what matters

  • A commit is a photo of the whole project with a caption and a date. None is ever deleted; you can go back to any of them.
  • Push sends the photos to GitHub; pull brings the ones others made. The local repository and the remote one are complete copies.
  • Commit messages say what changed and why: "Add exercise 3 (functions)" and not "stuff".
  • From Friday, every lesson starts with a git clone. Later, the group project lives entirely on GitHub, with branches and pull requests.
