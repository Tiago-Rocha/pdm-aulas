From JSON to a model

The API's GET /v1/trails returns a list of trails. Each one arrives like this (shortened):

{
  "id": "montanha-do-pico",
  "name": "Montanha do Pico",
  "islandId": "pico",
  "distanceKm": 7.6,
  "duration": "7 h"
}

Three pieces to bring it into the app: the model Trail, the fromJson that reads one map, and the repository that reads the list. The same path as the islands, now with trails.

Before the game, ask: "which JSON fields does the app need to show a list of trails?". distanceKm is the trap: 7.6 always looks like a double, but the API may send 7.

Game: from JSON to a model

Three ordering exercises. In the model, the right lines lock in place; the fields can come in any order, as can the required lines. In fromJson, the four fields too. The list is the same as the islands one in HttpForecastRepository.

Definition of done

An issue is only closed when the pull request meets all of this. If one point fails, it is not done, however much it "works on my laptop".

  1. It runs on a phone, not only in Chrome or the emulator.
  2. flutter analyze without warnings.
  3. It handles the loading, error and empty states.
  4. It was reviewed and approved by another member of the group.
For the tests "Done" is an objective list, not an opinion.

Game: is it done?

One scenario at a time, all together. Wait for everyone: we review each answer together.

  1. Read the scenario and vote on your own.
  2. Discuss with the person next to you: why that answer? Convince them, or let them convince you.
  3. Vote again. Only then do you see the answer.
Everyone goes at the same pace: say "scenario 1", let them vote, give the pairs a minute to discuss, second vote, and move to the board on the next slide. The first vote is the one that counts for the dot on the board; what matters is the change between the first and the second. If the first vote already has more than 70% right, there is no point discussing: move on.

Is it done? The class

Compare the two bars of each scenario: if the second vote has more right answers, the discussion worked. The analyze warnings scenario usually splits the class: it is worth hearing those who say "they are only warnings".
