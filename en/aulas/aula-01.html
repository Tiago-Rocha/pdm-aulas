Five tools: what each one is

Two minutes with the diagram on the projector; go through the cards in order: workplace, toolbox, parts supplier, album, shared copy, and where the app runs. The usual question: "what is Android Studio for if we write in VS Code?" For the parts (SDK) and for the emulator; it may never be opened for editing. Each tool comes up again when it is used.

Before downloading: the working folder

  1. Windows: open File Explorer → This PC → Local Disk (C:) → right-click → New → Folder → name it dev. Result: C:\dev.
  2. macOS and Linux: in the Terminal, mkdir ~/dev.
  3. This folder is for the Flutter SDK and for the projects. Never in OneDrive, nor in Documents or Desktop, nor in paths with spaces or accents.
Downloading and installing are different moments The installers that follow land in the browser's Downloads folder, and that does not matter. Each program installs itself into its default folder when the installer runs. The only folder choice in the whole setup is the Flutter SDK download, later on, and the answer is C:\dev.
Check around the room that nobody creates the folder inside OneDrive. On many new laptops, Documents and Desktop are OneDrive; hence C:\dev straight at the root of the disk.

How Flutter draws the screen

Analogy A cinema. The operating system lends the room and the screen; Flutter is the projector, which paints each image; the app's code is the script that says what appears in each scene.
Do not name the three layers yet (framework, engine, embedder): that is tomorrow. Here "describe, paint, show" is enough. If they ask about performance: the engine is native C++ code and paints straight onto the graphics card.

Install 1 of 4: Git

  1. Open the installer (Git-….exe) from Downloads. Accept the licence and click Next on every screen, with two exceptions.
  2. Screen Choosing the default editor used by Git: if VS Code is already installed, choose Use Visual Studio Code as Git's default editor; if not, leave it as it is (you change it later, in the guide).
  3. Screen Choose a credential helper: confirm Git Credential Manager. It is what lets you sign in to GitHub through the browser instead of typing passwords.
  4. Everything else: Next, Next, Install, Finish. The installation goes to Program Files\Git.
  5. Confirm in a new terminal: git --version.
macOS and Linux There is no installer: xcode-select --install on macOS, sudo apt-get install git on Linux.
The Git installer has a dozen screens and looks scary; say that only two matter. There are no screenshots of these windows (they are Windows dialogs); if you like, take them on a laptop from the class for next time.

Install 2 of 4: VS Code and the Flutter extension

  1. Open VSCodeUserSetup-x64-….exe. Accept the licence. On the Select Additional Tasks screen, tick Add to PATH and Add "Open with Code" action. Install, Finish.
  2. Open VS Code. Extensions menu: Ctrl+Shift+X. Type Flutter in the search box and install the Flutter extension, author Dart Code, the first in the list. It brings the Dart extension with it.

Install 3 of 4: Flutter SDK, from VS Code

  1. Command palette: Ctrl+Shift+P. Type flutter new and choose Flutter: Create New Project.
  2. When it asks for the SDK: Download SDK. In the folder window, choose C:\dev. Click Clone Flutter and wait (about 2 GB).
  3. When it finishes: Add SDK to PATH. If a notice about Google Analytics appears, OK.
  4. Close VS Code and every terminal and open them again. In a new terminal: flutter --version.
If the command does not show up in the palette, the folder is in Restricted Mode or the extension did not install. If flutter --version says "is not recognized", 90% of the time it is an old terminal; the other 10% is the PATH by hand, in the guide.

Windows: Developer Mode

Flutter needs to create symlinks when it builds plugins, and Windows only allows that with Developer Mode switched on. Without it, the error Building with plugins requires symlink support shows up later.

  1. In a terminal: start ms-settings:developers. Or Start menu → Developer settings.
  2. Turn on the Developer Mode switch and confirm the warning.

Install 4 of 4: Android Studio and the SDK

  1. Open android-studio-…-windows.exe: Next on everything, Install, Finish. On first launch choose Standard, accept the licences and let it download the SDK (3 to 4 GB). If the Windows user name has spaces or accents, choose Custom and put the SDK in C:\dev\Android\Sdk (guide).
  2. On the welcome screen: three-dot menu (More Actions) → SDK Manager → SDK Tools tab → tick Android SDK Command-line Tools (latest) → Apply → OK.
  3. In a terminal: flutter doctor --android-licenses and y to everything. Then flutter doctor: ✓ on Flutter, Android toolchain and Android Studio.
The SDK is still downloading on many laptops when you get here; it is left for home. What must be done today is step 3, Flutter (flutter --version answering).
