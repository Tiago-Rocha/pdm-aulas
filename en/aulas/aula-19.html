What we saw, and how to fix it

What we sawHow to fix it
Commits made straight to mainSettings, Branches, a rule for main: Require a pull request before merging. From then on, everything goes through a PR.
Open PRs with nobody reviewingIn the PR, under Reviewers, pick a teammate. They open Files changed, comment and click Approve. Only then the merge.
Red CI: The name 'MyApp' isn't a classThe template's test/widget_test.dart still uses the old app. Swap MyApp for your app's class, or delete the counter test.
Red CI: use_full_hex_values_for_flutter_colorsColor(0xFFFFFF) has 6 digits and is transparent. A colour takes 8: Color(0xFFFFFFFF), with FF in front.
In colours, the first two digits are the opacity (alpha): with 6 digits, alpha is 0 and the colour is transparent. Only the repository owner can switch on the main rule; on a private repository in a free account it may not be available, and then it stays as a rule agreed within the group.

In the test, watch out for

The trapWhat is true
"It is async, so it does not block"await only frees the thread while waiting; heavy computing still blocks.
"A 404 throws an exception"Not in http: the response arrives and you have to check the statusCode.
"Repeat the request after a timeout"Only if it is idempotent: GET yes, POST no.
"A JWT is encrypted"No: anyone can read it; the signature only stops it being changed.
"It runs in Chrome, it is done"Chrome is not a phone: the definition of done asks for the phone.
"Tokens in shared_preferences"Tokens in flutter_secure_storage; preferences in shared_preferences.
During the test First answer what you know for sure, then go back to the rest. Rule out the two clearly wrong options. Wrong answers do not lose marks: do not leave any blank.
