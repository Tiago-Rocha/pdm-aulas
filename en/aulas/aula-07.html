3. Stack and Positioned: image with text on top recap

SizedBox(
  height: 200,
  child: Stack(
    fit: StackFit.expand,                          // children with no position fill everything
    children: [
      Image.asset('assets/img/sao_miguel.jpg', fit: BoxFit.cover),
      const DecoratedBox(
        decoration: BoxDecoration(
          gradient: LinearGradient(
            begin: Alignment.topCenter,
            end: Alignment.bottomCenter,
            colors: [Colors.transparent, Colors.black54],   // darkens so the text is readable
          ),
        ),
      ),
      Positioned(
        left: 16,
        bottom: 16,
        child: Text('São Miguel', style: textTheme.headlineMedium?.copyWith(color: Colors.white)),
      ),
    ],
  ),
)
Ask the class If I remove fit: StackFit.expand, what happens to the image? How would I put the text at the top right? And if I swapped the order of the image and the gradient in the list?
  • Stack overlays its children in list order: the last one ends up on top. Positioned anchors a child to one or more edges.
  • A gradient on top of the image is a common technique in travel apps to guarantee contrast for the text.
Answers to the questions. Without StackFit.expand the children with no Positioned are no longer forced to fill the Stack: the image takes whatever size fits while keeping its aspect ratio, pinned to the top left, and an empty strip may be left beside it; the gradient, which has no child, shrinks to zero and disappears. Text at the top right: Positioned(top: 16, right: 16). With the order swapped, the gradient ends up under the image and can no longer be seen: the last one in the list is the one on top.

4. ListView and GridView

// A few known items: builds them all at once
ListView(
  children: const [ListTile(title: Text('Ponta Delgada')), ListTile(title: Text('Horta'))],
)

// Long list: builds only the visible items, as you scroll
ListView.separated(
  itemCount: forecasts.length,
  separatorBuilder: (_, _) => const Divider(height: 1),
  itemBuilder: (context, i) {
    final f = forecasts[i];
    return ListTile(
      leading: Icon(f.type.icon),
      title: Text(f.weekday),
      trailing: Text('${f.tMin.round()}° / ${f.tMax.round()}°'),
    );
  },
)

// Grid for the nine islands
GridView.count(
  crossAxisCount: 3,
  children: [for (final i in islands) Card(child: Center(child: Text(i.name)))],
)
Ask the class If the list had a thousand days, which of the two versions would freeze the app? How do I make the list of days horizontal? How do I make the grid have two columns on a phone and four on a tablet without writing two layouts?
Answers to the questions. The first one would freeze: ListView(children: [...]) has to create the thousand widgets before showing the first; .builder and .separated only call the itemBuilder for the ones on screen. Horizontal: scrollDirection: Axis.horizontal, and the list needs a height given by the parent (a SizedBox), because inside another vertical list the height is infinite. Two or four columns without two layouts: GridView.extent(maxCrossAxisExtent: 200), which fixes the maximum width of a cell and works out the columns from the available width. All three answers are on the next slide: let the class answer first.

4. Lists: what matters

  • ListView(children: [...]) builds all the children, even the ones you cannot see. For 10 items it is fine; for 1000, it freezes the app.
  • ListView.builder and .separated call the itemBuilder only for the visible items and recycle them as you scroll. That is how the Instagram feed copes with thousands of posts.
  • ListTile is the ready-made Material list row: leading, title, subtitle, trailing, onTap. Use it before inventing your own.
  • GridView.count fixes the number of columns; GridView.extent fixes the maximum width of each cell and works out the columns, which is better for tablets.
  • scrollDirection: Axis.horizontal turns any list into a sliding row.

For the tests: ListView.builder builds the items on demand; ListView with children builds them all.
