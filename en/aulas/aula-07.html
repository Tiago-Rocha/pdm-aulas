3. Stack and Positioned: the island header recap

/// Island photo with a gradient so that text on top of it stays readable.
class IslandHeader extends StatelessWidget {
  const IslandHeader({super.key});

  @override
  Widget build(BuildContext context) {
    return SizedBox(
      height: 200,
      child: Stack(
        fit: StackFit.expand, // children without a position fill the box
        children: [
          Image.asset(currentIsland.image, fit: BoxFit.cover),
          const DecoratedBox(
            decoration: BoxDecoration(
              gradient: LinearGradient(
                begin: Alignment.topCenter,
                end: Alignment.bottomCenter,
                colors: [Colors.transparent, Colors.black54],
              ),
            ),
          ),
          // TODO 2: add the island name at the bottom left (Positioned) and
          // a Chip with the weather description at the top right.
        ],
      ),
    );
  }
}
Ask the class If I remove fit: StackFit.expand, what happens to the image? And if I swapped the order of the image and the gradient in the list? Where in the list does the island name have to go to end up on top of both?
  • Stack overlays its children in list order: the last one ends up on top. Positioned anchors a child to one or more edges.
  • A gradient over the image is a common technique in travel apps to guarantee contrast for the text.
Answers to the questions. Without StackFit.expand the children without Positioned are no longer forced to fill the Stack: the image takes whatever size fits while keeping its proportions, pinned to the top left, and an empty strip may be left beside it; the gradient, which has no child, shrinks to zero and disappears. Swapping the order puts the gradient underneath the image, where it cannot be seen: the last one in the list is the one on top. That is why the island name goes at the end of the list, where the TODO 2 is, inside a Positioned: that is step 2.

Ask the class If the list had a thousand days, which of the two would freeze the app? Why does DaysRow wrap the list in a SizedBox with a height? What is the separatorBuilder for?
Answers to the questions. The first one would freeze: ListView(children: [...]) forces all the widgets to be created before the first one is shown; .builder and .separated only call the itemBuilder for the ones on screen. The SizedBox gives the horizontal list a height: inside the vertical ListView the available height is infinite and the list would not know how tall to be. The separatorBuilder builds what goes between two consecutive items, here 8 of space; it is called one time fewer than the itemBuilder.

4. GridView: the grid of islands

return GridView.extent(
  maxCrossAxisExtent: 160, // as many columns as fit, each up to 160 dp
  padding: const EdgeInsets.all(16),
  mainAxisSpacing: 8,
  crossAxisSpacing: 8,
  shrinkWrap: true, // takes only the height it needs, inside the ListView
  physics: const NeverScrollableScrollPhysics(), // the ListView scrolls
  children: [
    for (final i in islands)
      Card(
        clipBehavior: Clip.antiAlias,
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          children: [
            Expanded(child: Image.asset(i.image, fit: BoxFit.cover)),
            Padding(
              padding: const EdgeInsets.all(8),
              child: Text(i.name, textAlign: TextAlign.center),
            ),
          ],
        ),
      ),
  ],
);
Ask the class How many columns does the grid have on a phone 360 dp wide? And in a browser window 1200 wide? Why does this grid need shrinkWrap and no scrolling of its own?
Answers to the questions. GridView.extent does not fix the number of columns: it uses as many as it takes for no cell to be wider than 160 dp. At 360 dp wide that gives 2 columns, on a 411 dp phone 3, and in a 1200 window 7. Anyone in Chrome can watch this live by widening the window. shrinkWrap makes the grid take only the height it needs and NeverScrollableScrollPhysics switches off its scrolling, because the outer ListView is the one that scrolls. Without shrinkWrap, a list inside another one fails with "Vertical viewport was given unbounded height".

4. Lists: what matters

  • ListView(children: [...]) builds all the children, even the ones you cannot see. For 10 items it is fine; for 1000, it freezes the app.
  • ListView.builder and .separated call the itemBuilder only for the visible items and recycle them as you scroll. That is how the Instagram feed copes with thousands of posts.
  • ListTile is the ready-made Material list row: leading, title, subtitle, trailing, onTap. Use it before inventing your own.
  • GridView.count fixes the number of columns; GridView.extent fixes the maximum width of each cell and works out the columns, which is better for tablets.
  • scrollDirection: Axis.horizontal turns any list into a sliding row.

For the tests: ListView.builder builds the items on demand; ListView with children builds them all.
