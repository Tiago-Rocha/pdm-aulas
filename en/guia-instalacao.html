Week 1 · lessons 1 to 4

Setup guide

Goal of the first week: Flutter, Git and GitHub working on your laptop, with the sample app running on an Android phone or on the emulator. Installation starts in lesson 1, while the downloads run during the theory part, and finishes at home over the week. This guide gives priority to Windows, which is the system most of the class uses; macOS and Linux have their own, shorter sections. The screenshots were taken on macOS; on Windows the VS Code and Android Studio windows look the same.

Before you install anything at all
  • Working folder: create C:\dev (Windows) or ~/dev (macOS and Linux). Everything you install or clone goes there.
  • Never inside OneDrive, Documents, Desktop or Program Files. On Windows, Documents and Desktop are usually synced with OneDrive, and that breaks Flutter and Git.
  • No spaces or accents in the path. If your Windows user is called João Silva, that is one more reason to use C:\dev and not C:\Users\João Silva\....
  • Disk space: at least 15 GB free. Android Studio and the SDK take about 8 GB; Flutter, 2 GB.

Downloading and installing are two different moments

The downloaded files (the installers) land in the browser's Downloads folder, and it does not matter where. The program is only installed when you run each installer, and in most cases without asking where. The only moment you choose a folder is the Flutter SDK download from VS Code, and there the answer is C:\dev.

DownloadWhat it isWhen installing
Git for Windows (Git-…-64-bit.exe)InstallerInstalls into Program Files\Git without asking. Just click Next; confirm the Credential Manager.
VS Code (VSCodeUserSetup-x64-….exe)InstallerInstalls into AppData\Local\Programs without asking. Only the Add to PATH box matters.
Android Studio (android-studio-…-windows.exe)InstallerInstalls into Program Files\Android without asking. On first launch, Standard puts the SDK in AppData\Local\Android\Sdk; only Custom asks where.
Flutter SDKNot a manual downloadThe Download SDK button in VS Code downloads it straight into the folder you choose: C:\dev. It is the only folder choice in the whole installation.

At the end, the installers can be deleted from Downloads; you will not need them again.

Where each thing lives

The C:\dev rule applies to the Flutter SDK and to your projects. Programs install into their default folders.

WhatWhere it livesNotes
Git, VS Code, Android StudioThe installer's default folder (Program Files or AppData\Local)They are programs; there is no reason to move them.
GitHubNot installedIt is a web service. What you install is Git; GitHub is where Git sends the copies.
Flutter SDKC:\dev\flutterIt is a folder that Flutter updates by itself; it needs a simple path outside OneDrive.
Projects and cloned repositoriesC:\dev\project-nameEvery flutter create and every git clone goes here.
Android SDKBy default C:\Users\<name>\AppData\Local\Android\SdkFine if your user name has no spaces or accents. If it has, see the box below.
Windows user with spaces or accents in the name If your home folder is something like C:\Users\João Silva, Gradle and the NDK will fail with the SDK and cache paths. Three adjustments, once:
  1. On the first launch of Android Studio choose the Custom installation and set Android SDK Location to C:\dev\Android\Sdk. If you have already installed it, change it in SDK Manager → Android SDK Location → Edit.
  2. Create two user environment variables (Start menu → environment variables → Edit environment variables for your account → New): GRADLE_USER_HOME = C:\dev\.gradle and PUB_CACHE = C:\dev\.pub-cache.
  3. Close and reopen the terminals and VS Code. Confirm with flutter doctor -v that the Android SDK shows up in C:\dev\Android\Sdk.

Do you already have any of these tools?

Students coming from the first year often have VS Code installed; Git, as a rule, not. In a terminal (Start menu → Terminal):

git --version
code --version
  • Git "is not recognized": the usual case. Install Git for Windows (Step 1).
  • Git answers with 2.4x or higher: done. Confirm that the Credential Manager is there (git config --global credential.helper should answer manager); if not, reinstall Git for Windows over the existing one.
  • VS Code already installed: Help → Check for Updates (the Flutter extension needs a recent version) and go straight to Step 2, the Flutter SDK, which is a 2 GB download and is best started early.
  • Old projects in Documents or on OneDrive: no problem; the ones for this course go in C:\dev.

Windows, step by step

Tested with 64-bit Windows 10 and 11. You need an account with permission to install programs.

Step 1: Git, VS Code and Android Studio

  1. Git for Windows. Run the installer with the default options, with two things to confirm: in Choosing the default editor choose Use Visual Studio Code as Git's default editor (if VS Code is already installed; otherwise leave Vim, you can change it later), and confirm that Git Credential Manager is selected. It is what will let you sign in to GitHub through the browser without typing passwords.
  2. Visual Studio Code. User Installer. Tick Add to PATH and Add "Open with Code" action. When it finishes, open it and install the Flutter extension (author Dart Code) from the Extensions menu, Ctrl+Shift+X, typing "Flutter" in the search box. It is the first in the list.
  3. Android Studio. Installer with the default options. On first launch choose the Standard installation and accept the licences: it downloads the SDK, the platform-tools and an emulator. Let it run; come back here when it finishes. At the end the welcome screen below appears.
  4. Windows Developer Mode. Flutter needs it to create symlinks when it builds plugins. Open the Start menu, type Developer settings (or run start ms-settings:developers in a terminal) and turn on the Developer Mode switch; confirm the warning. Without this, the error Building with plugins requires symlink support shows up later.

Step 2: Flutter SDK through VS Code

  1. In VS Code open the command palette, Ctrl+Shift+P, type flutter new and choose Flutter: Create New Project (the documentation still calls it "Flutter: New Project"; it is the same command).
  2. When it asks for the SDK, choose Download SDK.
  3. In the folder window choose C:\dev. The SDK ends up in C:\dev\flutter.
  4. Click Clone Flutter and wait. If it seems stuck for more than 15 minutes, cancel and try again.
  5. When it appears, click Add SDK to PATH. If a notice about Google Analytics appears, click OK.
  6. Close VS Code and every terminal and open them again. The PATH only applies to new windows.
  7. Open a new terminal (Start menu → Terminal or PowerShell) and confirm: 
    flutter --version
    It should answer with Flutter 3.4x and Dart 3.1x. If it says that flutter is not recognized, see the common problems.
Manual alternative If the download through VS Code fails, download the stable channel zip from docs.flutter.dev/install/archive and extract it to C:\dev (giving C:\dev\flutter). Then: Start menu → type environment variables → Edit environment variables for your account → under User variables open Path → New → type C:\dev\flutter\bin → OK on everything. Close and reopen the terminals.

Step 3: Android SDK and licences

  1. In Android Studio: welcome screen → three-dot menu (More Actions) → SDK Manager. It opens the Settings window at the Android SDK section.
  2. SDK Platforms tab: the most recent platform (API 36 or higher) should have the status Installed. The Android SDK Location line at the top says where the SDK went; write it down.
  3. SDK Tools tab: tick Android SDK Command-line Tools (latest), as well as Build-Tools, Platform-Tools and Emulator, and click Apply and then OK. The command-line tools are the component that is most often missing.
  4. In a terminal accept the licences, answering y to all of them: 
    flutter doctor --android-licenses
  5. Diagnosis: 
    flutter doctor
    You need ✓ on Flutter, Android toolchain and Android Studio. Warnings about Visual Studio (it is for Windows desktop apps) and Chrome can be ignored.

What the PATH is, and when you need to touch it

When you type flutter in a terminal, Windows has to find out where the program with that name is. It looks for it in a list of folders called PATH. If the folder C:\dev\flutter\bin is not in that list, Windows answers that the command is not recognized, even with Flutter installed.

The PATH is an environment variable: a named value, stored by Windows, that every program can read. It is not a file you edit; you change it in a settings window. The Add SDK to PATH button in VS Code makes that change for you, and as a rule you do not need to do anything else. You only change it by hand if, in a new terminal, flutter --version still says the command is not recognized.

Changing the PATH by hand (only if you need to)

  1. Open the Start menu and type environment variables. Choose Edit environment variables for your account (in Portuguese, Editar as variáveis de ambiente da conta). The Environment Variables window opens.
  2. In the top half, User variables, select the Path line and click Edit….
  3. In the next window click New, type C:\dev\flutter\bin and click OK. Then OK in the previous window, and OK again.
  4. Close every terminal and VS Code, open a new terminal and run flutter --version.
The other variables in this guide GRADLE_USER_HOME and PUB_CACHE, in the box for users with accents in their name, are created in the same window: under User variables click New…, type the name in one box and the value in the other, and OK.

Step 4: Windows Defender and antivirus

Defender scans every file that Flutter and Gradle write, and that makes the first build much slower; some antivirus programs even delete flutter.bat. Add C:\dev to the exclusions: Settings → Privacy & security → Windows Security → Virus & threat protection → Manage settings → Exclusions → Add a folder.

macOS, step by step

  1. Terminal: xcode-select --install. It installs the command-line tools, which include Git. On a Mac with an Apple chip, if asked, also install Rosetta: softwareupdate --install-rosetta.
  2. Install VS Code and the Flutter extension.
  3. Install Android Studio with the Standard installation.
  4. In VS Code: ⌘+Shift+P → Flutter: Create New Project → Download SDK → folder ~/dev → Clone Flutter → Add SDK to PATH. Close and reopen the Terminal.
    Manual alternative: extract the zip to ~/dev and run echo 'export PATH="$HOME/dev/flutter/bin:$PATH"' >> ~/.zprofile.
  5. Android Studio SDK Manager: Android SDK Command-line Tools. Then flutter doctor --android-licenses and flutter doctor.
  6. Optional, for iOS: install Xcode from the App Store (more than 10 GB), then sudo sh -c 'xcode-select -s /Applications/Xcode.app/Contents/Developer && xcodebuild -runFirstLaunch', sudo xcodebuild -license, xcodebuild -downloadPlatform iOS and CocoaPods. It is not required for the course.

Linux (Ubuntu and Debian), step by step

  1. Base packages: 
    sudo apt-get update -y && sudo apt-get upgrade -y
sudo apt-get install -y curl git unzip xz-utils zip libglu1-mesa
  2. Install VS Code (.deb package) and the Flutter extension; install Android Studio with the Standard installation.
  3. In VS Code: Ctrl+Shift+P → Flutter: Create New Project → Download SDK → folder ~/dev → Clone Flutter → Add SDK to PATH. Close and reopen the terminal.
    Manual alternative: tar -xf ~/Downloads/flutter_linux_*-stable.tar.xz -C ~/dev/ and echo 'export PATH="$HOME/dev/flutter/bin:$PATH"' >> ~/.bashrc.
  4. SDK Manager: Android SDK Command-line Tools. Then flutter doctor --android-licenses and flutter doctor.
  5. For the phone over USB: sudo apt-get install -y android-sdk-platform-tools-common and sudo usermod -aG plugdev $USER; log out and log back in.

Git and GitHub

On every system. The goal is for you to be able to clone, change, commit and push from VS Code by the end of the week.

  1. GitHub account. Create one at github.com/signup with your school or personal email. The user name will appear on your CV: choose one you can show to an employer. Confirm the email.
  2. Identity in commits. In a terminal, with your name and the email of your GitHub account: 
    git config --global user.name "First Last"
git config --global user.email "your-email@example.com"
git config --global init.defaultBranch main
    If you installed Git before VS Code, set the editor now: git config --global core.editor "code --wait".
  3. Full test. On GitHub, click New repository, call it pdm-test, tick Add a README file and create it. Copy the repository URL (green Code button → HTTPS). Then, in VS Code: command palette → Git: Clone → paste the URL → choose the folder C:\dev (or ~/dev) → Open when it asks.
  4. If a yellow Restricted Mode notice appears when you open the folder, click Manage and then Trust. VS Code asks this question for any folder it does not know yet; without trust, the extensions, including the Flutter one, stay switched off.
  5. Edit README.md, add a line, save (Ctrl+S). Open the Source Control view: the icon with three connected circles in the bar on the left, or palette → View: Show Source Control. Type a message in the box, click Commit and then Sync Changes (or Publish Branch).
  6. The first time, Git Credential Manager opens the browser for you to authorise access to GitHub. Authorise it. You will not need a password again on this computer.
  7. Open the repository on GitHub and confirm that the change is there. From here on Git is working.
Windows: two useful settings git config --global core.longpaths true avoids errors with long paths in Flutter projects; core.autocrlf keeps the installer's default value (true), which is the right one on Windows.

Where to run the app: phone or emulator

You need one of the two by Friday's lesson; in the first lesson neither is needed. The phone is faster and more real; the emulator will do if you have no Android phone or cable, but it needs a laptop with 16 GB of RAM to be pleasant.

Option A: Android phone

  1. Developer options. Settings → About phone → tap 7 times on Build number (on some models it is under Software information or Version).
  2. USB debugging. Settings → System → Developer options → USB debugging. On Xiaomi and Redmi also turn on Install via USB.
  3. Cable. Use a data cable; many cheap cables only charge. On the phone choose File transfer if it asks, and accept Allow USB debugging for this computer, with "Always allow".
  4. Windows: if the phone does not show up in the next step, install the manufacturer's USB driver. For Google Pixel and many others, the Google USB Driver is installed through the SDK Manager, SDK Tools tab.
  5. Confirm: 
    flutter devices
    The model should appear with android-arm64. If unauthorized appears, there is a request waiting on the phone screen.
No cable Android 11 or higher has Wireless debugging in the developer options; pair with adb pair following this guide. It is slower than the cable.

Option B: Android emulator

  1. On Windows, the emulator needs the Windows Hypervisor Platform. Android Studio asks to enable it the first time and restarts the computer. If it does not ask: Start menu → Turn Windows features on or off → tick Windows Hypervisor Platform → OK → restart.
  2. Android Studio welcome screen → three-dot menu → Virtual Device Manager. The Device Manager opens; click the + to create a device.
  3. Choose Medium Phone or a recent Pixel, Next, accept the suggested system image (it downloads about 1 GB), Finish.
  4. Start it with the triangle in the Device Manager. When the Android screen appears, confirm in a terminal: 
    flutter emulators
flutter devices

Check and first app

The terminal can be the Windows one (Start menu → Terminal or PowerShell) or the VS Code one: Terminal → New Terminal menu, or Ctrl+`. It is the same thing.

  1. Full diagnosis: 
    flutter doctor -v
  2. Create and run the sample app, inside the working folder: 
    cd C:\dev
flutter create hello_mobile
cd hello_mobile
flutter run
    On macOS and Linux, cd ~/dev. If there is more than one device (phone and emulator), Flutter asks which one to use. The first build downloads Gradle and takes several minutes. When the app opens, tap the + button and watch the counter go up.
  3. With the app running, open the hello_mobile folder in VS Code, edit lib/main.dart, change a piece of text, save, and press r in the terminal. The change appears on the phone without restarting: that is hot reload.
